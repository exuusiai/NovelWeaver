# 单章大纲 → 正文：数据集构建策略提示词（v2）

> **任务**：训练一个模型，输入单章大纲，输出该章完整正文。
> **数据来源**：成品小说（已有 177 万字语料：三体/三国/首无/霍比特人）。
> **前置步骤**：从正文反向提取大纲（这一步本身后续也要训练成小模型）。
>
> **本文档供外部模型审核**。请重点审查大纲抽象度设计是否合理、提取提示词是否会引入"作弊"风险。

---

## 零、核心设计决策：大纲的抽象度

这是整个数据集的命脉，先明确：

```
太详细 ──────────────────────────────────── 太简略
  │                                            │
  接近正文的逐句摘要                    只有一句"叶文洁回忆往事"
  │                                            │
  模型学到的是"压缩→解压"              模型无法生成有内容的长文
  （退化为文本摘要的逆任务）           （退化为自由续写）
```

**目标抽象度**：一个作者在写这章**之前**会写下的细纲——他知道要发生什么、谁出场、场景怎么转，但还没写具体的句子。

具体来说，大纲应包含：

| 维度 | 包含 | 不包含 |
|---|---|---|
| 情节 | 场景序列、每场的目标/阻力/转折 | 具体对白原文、具体描写细节 |
| 人物 | 出场人物名、行为意图、情绪走向 | 人物的具体动作描写、心理独白 |
| 结构 | 场景切换点、时间跨度、POV | 段落划分、句子节奏 |
| 约束 | 必须承接的前文事实、不可违背的设定 | 原文的措辞和意象 |
| 长度 | 每场预计字数范围 | — |

**量化标准**：大纲字数 ≈ 正文字数的 3-8%。3000 字的章 → 90-240 字大纲。

## 一、数据集 JSON 格式

```json
{
  "id": "san-ti/ch004",
  "source": {
    "title": "三体",
    "author": "刘慈欣",
    "genre": "科幻",
    "chapter_index": 4,
    "chapter_title": "三十八年后·科学边界"
  },
  "input": {
    "chapter_outline": "本章分为三个场景。\n\n场景一：汪淼在家中观看宇宙，发现星星在闪烁。他起初以为是错觉，但闪烁有规律，让他感到不安。\n\n场景二：汪淼前往科学家聚会的咖啡馆。丁仪向他介绍了"科学边界"组织，提到最近有多名物理学家自杀。汪淼意识到这些死亡可能与某种他无法理解的现象有关。\n\n场景三：汪淼回家后上网查资料，发现一个名为"三体"的虚拟游戏。他戴上 VR 设备进入游戏，看到一个正在毁灭又重建的世界。\n\n视角：汪淼。承接：汪淼已从射电天文中心回来，接触了倒计时现象。",
    "context": {
      "pov": "汪淼",
      "characters_expected": ["汪淼", "丁仪"],
      "previous_summary": "上一章：汪淼在射电天文中心观测到宇宙背景辐射的异常波动，回来后眼前出现幽灵倒计时。",
      "word_target": 3000
    }
  },
  "output": "4 三十八年后·科学边界\n\n（正文全文……）",
  "extraction_metadata": {
    "model": "DeepSeek-V4.1-Flash",
    "confidence": 0.92,
    "outline_word_count": 156,
    "text_word_count": 3200,
    "compression_ratio": 0.049,
    "quality_flags": []
  }
}
```

### 设计说明

- **`chapter_outline`** 是核心输入——一段**自然语言文本**（不是结构化 JSON），因为训练时模型的输入就是这段文字。格式越接近真实作者写的细纲越好。
- **`context.previous_summary`** 是前一章的摘要（≤80字），让模型有"承接上文"的信号，不至于凭空开场。
- **`context.characters_expected`** 列出应出场人物，可作为生成后的自动校验维度。
- **`context.word_target`** 给出目标字数，训练模型控制篇幅。
- **`compression_ratio`** 是质量门指标（0.03-0.08 合格），防大纲过详或过略。

## 二、大纲提取提示词（从正文反向生成）

### 2.1 主提取（逐章）

```
系统提示词：
你是一个小说编辑。你的任务是阅读一章完整的小说正文，写出作者在写这章之前
可能拟好的细纲。细纲是给作者自己看的备忘，不是给读者的摘要。

关键原则：
1. 只写"发生了什么、谁做的、结果如何"——不写具体的句子、对话、描写细节
2. 按场景分段，每个场景用 2-3 句话概括（目标→阻力→转折）
3. 标注视角人物和需要承接的前文事实
4. 大纲字数控制在正文的 3-8%（3000字正文→90-240字大纲）
5. 不要复制原文中的句子或短语——用自己的话重新表述

用户提示词：
请阅读以下章节正文，生成作者视角的写作细纲。

输出格式（纯文本，不用 JSON）：

视角：[POV 人物名]
承接：[需承接的前文事实，一句话]

场景一：[2-3 句话概括]
场景二：[2-3 句话概括]
……

预计字数：[目标字数]

——

正文：
{chapter_text}

前一章摘要（供参考，不要在大纲中重复）：
{previous_summary or "（本章为第一章，无前文）"}
```

### 2.2 前章摘要生成（独立调用，供 context 用）

```
用户提示词：
用不超过 80 字概括以下章节的核心情节（谁做了什么、结果如何）。
不要描写细节，只写情节推进。

正文：
{chapter_text}
```

### 2.3 提取质量校验（LLM-as-judge）

```
系统提示词：
你是一个严格的编辑。以下是一章正文和从它提取的大纲。
请评估这份大纲是否达到了"作者写作前的细纲"标准。

评估维度（每项 0-100）：
1. 覆盖度：大纲是否覆盖了正文中的所有重要情节点？
2. 抽象度：大纲是否避免了复制原文的句子/短语？（过度详细 = 低分）
3. 结构性：场景划分是否合理，每场是否有明确的目标和转折？
4. 可操作性：一个作者拿这份大纲能否写出接近的正文？

返回 JSON：
{
  "coverage": 0-100,
  "abstraction": 0-100,
  "structure": 0-100,
  "actionability": 0-100,
  "compression_ratio": 0.03-0.08 合格 / 其他 = 不合格,
  "verdict": "pass | fail | revise",
  "issues": ["具体问题描述"],
  "suggestion": "修改建议（verdict=revise 时）"
}

正文：
{chapter_text}

大纲：
{chapter_outline}
```

## 三、流水线

```
对每部小说：
  1. 导入 → 章节切分（importer）
  2. 逐章生成前章摘要（2.2 提示词，串行，每章一次调用）
  3. 逐章提取大纲（2.1 提示词，串行，输入 = 正文 + 前章摘要）
  4. 逐章质量校验（2.3 提示词，可并行）
  5. 确定性规则过滤：
     - compression_ratio 不在 [0.03, 0.08] → 重提取一次 → 仍不合规 → 剔除
     - coverage < 60 → 重提取 → 仍低 → 剔除
     - abstraction < 60 → 剔除（大纲过度复制原文 = 作弊数据）
     - 正文字数 < 1000 或 > 8000 → 剔除
  6. 输出 JSONL（一行一章）
```

## 四、为什么不用结构化 JSON 做大纲格式

之前 v1 方案用 `{scenes: [{objective, obstacle, turn}], pov, entry_state, ...}` 结构化格式。放弃的原因：

1. **训练输入应该是自然语言**——真实用户给模型的"大纲"是自然语言文本，不是嵌套 JSON。模型学的输入分布应与推理时一致。
2. **结构化字段限制了表达力**——`objective`/`obstacle` 的固定字段无法表达"这段的情绪节奏是先压抑后爆发"这类信息。
3. **提取时强制结构化会增加模型负担**——提取模型需要同时做"理解正文"和"填格子"两件事，质量下降。

场景内的信息仍然可以用换行分段表达结构感，但不需要 JSON 嵌套。

## 五、审核关注点

1. **大纲抽象度的 3-8% 压缩比**：这个范围是否合理？短篇（1000字章）和长章（8000字章）是否需要不同的比例？

2. **"作弊"风险**：大纲由模型从正文提取，模型可能无意识地把正文的关键句嵌入大纲。SFT 时模型学到"从大纲中恢复嵌入的原文"而不是"从大纲创作正文"。当前的 `abstraction` 维度校验是否足以拦截？

3. **前章摘要的信息量**：80 字限制是否会太紧，导致模型缺乏足够的上下文信号来生成有承接感的长文？

4. **数据多样性**：4 部作品（科幻/历史/推理/奇幻）是否足够？需要多少部作品才能覆盖足够的写作风格多样性？

5. **提取的级联误差**：前章摘要→大纲→正文的对齐链，每步都有误差。是否应该直接从"正文+全局信息"一步提取大纲，跳过前章摘要的依赖？

6. **训练时的 input 格式**：是否需要在 `chapter_outline` 前后加 instruction wrapper（如 "根据以下细纲写出本章正文：\n\n{outline}\n\n正文："）？还是让模型隐式学习？

7. **字数控制**：`word_target: 3000` 作为输入信号，模型能否可靠地控制输出长度？是否需要在 SFT 时做长度分布分析？

8. **后续蒸馏提取模型**：当提取本身也要训练成小模型时，当前的大模型提取数据就是蒸馏的教师信号。这个数据（大纲, 正文）对能否支撑蒸馏？
